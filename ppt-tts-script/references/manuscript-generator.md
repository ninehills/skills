# 逐字稿生成（Step 3）详细指南

## 任务

基于素材库和大纲，按节生成口语化逐字稿。每页以 `[PAGE:N]` 标记分隔。

## 输入

- `02_outline/outline.json` — 演讲大纲（含节结构和风格提示）
- `01_materials/slide-XX.md` — 页面文字素材
- `01_materials/slide-XX.png` — 页面图片（Gemini 可读取）

## 使用 Gemini CLI 生成

Gemini CLI 能同时理解图片和文字，生成更贴合幻灯片视觉内容的口语化表述。这是本步骤的推荐方式。

### Gemini 调用模板

对每个节，构造以下 prompt 调用 Gemini：

```bash
scripts/gemini-task.sh -t 8 "TASK: 为第 ${sec_id} 节生成分节逐字稿

INPUT:
- 节标题: ${title}
- 页面范围: ${page_start}-${page_end} 页
- 预计时长: ${estimated_duration}
- 语速: ${speed}（快速=200字/分钟，中等=180字/分钟，慢速=150字/分钟）
- 风格提示: ${style_hint}
- 页面素材文字内容:
${slides_content}

OUTPUT FORMAT:
# ${title}

**页面范围**：${page_start}-${page_end} 页
**预计时长**：${estimated_duration}
**语速**：${speed}

**[PAGE:${page_start}]** \`slide-${page_start}.png\`

（该页口语化讲解内容）

**[PAGE:${page_start+1}]** \`slide-${page_start+1}.png\`

（该页口语化讲解内容）

REQUIREMENTS:
1. 每页开头使用 **[PAGE:N]** 标记
2. 口语化、自然流畅、适合朗读
3. 页面间有自然过渡（不说"第xx页"）
4. 语速按 ${speed} 调整字数
5. 忠实于素材内容，不添加未提及信息
6. 使用中文标点符号
7. 输出纯文本，不要用代码块包裹

FORBIDDEN — 以下内容绝对不能出现在输出中：
- 任何括号包裹的舞台指示或控制注释，例如：（语速放慢）（停顿）（恢复语速）（重点强调）（轻声）（加快语速）（深呼吸）
- 任何方括号包裹的导演标注，例如：[语速加快] [停顿3秒] [切换语气]
- 任何描述说话方式的元指令，例如："此处应放慢语速"、"以下用激动的语气"
- 任何非朗读内容的辅助说明文字

输出必须是纯粹的演讲文本——只包含演讲者会说出口的话。想象你在为一个 TTS 引擎提供输入，任何不该被念出来的文字都会被逐字朗读，造成灾难性后果。

ACTION: 现在生成逐字稿内容。"
```

如果需要 Gemini 同时读取图片，可以在调用前将图片路径包含在 prompt 中，或使用 Gemini 的文件引用功能。

### 并发处理

各节之间相互独立，可以通过 subagent 并发生成。每个 subagent 负责一个节：

1. 读取该节对应的 slide-XX.md 文字内容
2. 构造 Gemini prompt
3. 调用 `scripts/gemini-task.sh` 执行
4. 解析输出，保存为 `03_manuscript/section-XX.md`

### 速度参数

除非用户指定，语速默认为**快速**（200字/分钟）。

| 语速 | 字/分钟 | 适用场景 |
|------|---------|----------|
| 快速 | 200 | 技术分享、产品演示 |
| 中等 | 180 | 商业汇报、培训 |
| 慢速 | 150 | 学术报告、正式演讲 |

## 降级方案（无 Gemini CLI）

Gemini CLI 不可用时，按以下步骤判断是否可以继续：

### 步骤 1：检测当前模型的图片输入能力

用 `read` 工具读取 `01_materials/` 中的任意一张 `slide-XX.png`，然后尝试用一句话描述图片内容。

- 如果能识别图片内容（比如能说出“这是一张包含柱状图的幻灯片”），说明当前模型支持视觉输入 → 继续步骤 2
- 如果无法识别（read 工具报错或模型无法理解图片内容）→ **中止执行**，向用户报告：

  > ⚠️ Gemini CLI 未安装，且当前模型不支持图片输入。逐字稿生成需要理解幻灯片的视觉内容（图表、截图、布局等），仅依赖文字无法产出合格结果。
  > 请安装 Gemini CLI 或切换到支持视觉输入的模型后重试。

### 步骤 2：用 subagent + 模型视觉能力生成

当模型具备图片能力时，每个节的逐字稿通过 subagent 生成。subagent 的 task 按以下模板构造：

```
你是一位演讲稿撰写专家。请为第 ${sec_id} 节生成口语化逐字稿。

## 信息
- 节标题: ${title}
- 页面范围: ${page_start}-${page_end} 页
- 预计时长: ${estimated_duration}
- 语速: ${speed}（快速=200字/分钟，中等=180字/分钟，慢速=150字/分钟）
- 风格提示: ${style_hint}

## 执行步骤
1. 用 read 工具依次读取以下文件（图片和文字都要读）：
   ${slide_files_list}
2. 结合图片视觉内容和文字内容，为每页生成口语化讲解
3. 将结果写入 ${output_path}

## 输出格式
# ${title}

**页面范围**：${page_start}-${page_end} 页
**预计时长**：${estimated_duration}
**语速**：${speed}

**[PAGE:${page_start}]** `slide-${page_start}.png`

（该页口语化讲解内容）

## 规则
1. 每页开头用 **[PAGE:N]** 标记
2. 口语化、自然流畅、适合朗读
3. 页间有自然过渡，不说"第xx页"
4. 语速按 ${speed} 调整字数
5. 忠实于素材，不添加未提及信息
6. 使用中文标点符号

## 禁止内容
绝对不能输出以下内容：
- 括号包裹的舞台指示：（语速放慢）（停顿）（恢复语速）
- 方括号包裹的标注：[语速加快] [停顿3秒]
- 元指令："此处应放慢"、"以下用激动语气"
- 任何非朗读内容的辅助说明
输出必须是纯粹的演讲文本，只包含演讲者会说出口的话。
```

这种方式和 Gemini 方案的主要差异是：图片由当前模型通过 read 工具直接读取，而不是通过 Gemini CLI 传入。其余格式要求、禁止规则、输出结构完全一致。

## 输出格式

### section-XX.md

```markdown
# 第1节：开场与公司介绍

**页面范围**：1-5 页
**预计时长**：5 分钟
**语速**：快速

**[PAGE:1]** `slide-01.png`

各位来宾，大家好。今天非常高兴能在这里和大家分享...

**[PAGE:2]** `slide-02.png`

我们今天的议程有三个部分...

**[PAGE:5]** `slide-05.png`

以上就是关于我们公司的简要介绍，接下来让我们看看今天的主角——
```

### manuscript.json

```json
{
  "total_sections": 4,
  "total_words": 8000,
  "sections": [
    {
      "id": "sec-01",
      "file": "section-01.md",
      "page_start": 1,
      "page_end": 5,
      "word_count": 1500
    }
  ]
}
```

## 质量要求

- 每页都有 `[PAGE:N]` 标记
- 口语化程度良好，适合朗读
- 页码范围与 outline.json 一致
- 页间有自然过渡，不生硬
- 忠实于素材内容，不捏造信息
- **绝对不包含任何控制指令**：不允许出现（语速放慢）、（停顿）、（恢复语速）、[强调]、"此处放慢"等任何非朗读内容。输出必须是纯粹的演讲者会说出口的话。
